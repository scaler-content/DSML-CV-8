    How does a self-driving car detect pedestrians, vehicles and traffic lights in real time? Single-stage detectors skip the region-proposal step and predict boxes and classes in one pass. We study SSD and YOLO, decode a pre-trained YOLOv5 by hand, test it under bad conditions, and see why class imbalance is their weak spot and how focal loss fixes it.

    01

    Why single-stage detectors?

    You are a Machine Learning Engineer on Tesla’s Autonomous Driving team, building a prototype that detects and locates traffic lights and stop signs, other vehicles (cars, bicycles, trucks), pedestrians and animals on the road, using the dashboard camera. The detector must run inference in real time on commodity hardware (CPU only) and be accurate enough to be safe.

    Problems with R-CNNs

    1

    Training has multiple phases

    The Region Proposal Network is trained to propose boxes, and the detector that classifies them is trained separately. Faster R-CNN uses a 4-step alternating scheme (joint training is also possible).

    2

    Training is slow

    Several moving parts, the RPN, the ROI pooling module and the final classifier, each add to training time.

    3

    Inference is too slow

    Faster R-CNN with a VGG-16 backbone runs at about 5 fps on a GPU: far from real time on CPU-only hardware.

    The single-stage idea

    Single-stage detectors have no region proposal step. They treat detection as a regression problem: one forward pass over the image directly outputs class probabilities and bounding-box coordinates. The two well-known families are SSD (Single Shot MultiBox Detector) and YOLO (You Only Look Once).

    02

    SSD: Single Shot MultiBox Detector

    (Paper.) The core idea: a CNN takes an image and produces detections at different scales, shapes and locations in one pass.

    Architecture

    • SSD builds on VGG-16 (the base network), truncated after conv5_3.
    • The fully connected layers fc6 and fc7 become convolutional layers; fc8 and the dropout layers are removed.
    • New convolutional layers are added on top: these extra layers are what make SSD work.
    • Every layer is convolutional, so the network is fully convolutional.

    The feature maps shrink with depth, as in a standard CNN, and several of them feed the detection step directly. So SSD extracts features at multiple scales: the large, early maps help with small objects, the small, deep maps with large objects.

    Locations, shapes and scales in one pass

    Locations: grids

    The first two dimensions of a feature map can be read as a grid laid over the input image (a 5×5 map divides the image into a 5×5 grid, a 3×3 map into 3×3). Objects can be detected at every location of every map.

    Shapes: default boxes

    Predefined boxes of several scales and aspect ratios, centred on each feature-map cell. SSD300 uses 4 or 6 per cell: 4 on conv4_3, conv10_2 and conv11_2, 6 on the other layers.

    The detection module runs a multiclass classifier and a bounding-box regressor on each selected feature map, so results cover different shapes, scales and locations. To try SSD in PyTorch, see torchvision.models.detection.ssd300_vgg16 and ssdlite320_mobilenet_v3_large.

    MultiBox regression
    
  
    SSD’s box regression is inspired by Szegedy’s MultiBox work, a fast, class-agnostic way to propose box coordinates. MultiBox uses an Inception-style convolutional network, whose 1×1 convolutions reduce the number of channels while keeping the width and height.
    
  
    
  
    SSD loss
    
  
      
    
    • Confidence loss: softmax cross-entropy over the classes, with background as one class.
      • 
    
    • Location loss: Smooth L1 between predicted and true box offsets, counted only for default boxes that match an object.
      • 
  
    
  
    loss = (1 / N) × (confidence_loss + α × location_loss)
    N is the number of matched default boxes and α is 1 in the paper. A default box matches an object when their IoU is above 0.5.
    
  
    Almost every default box is background, so SSD keeps only the hardest negatives, at most 3 for every positive: hard negative mining.
    
  
    

    

    


    

    
  03
  
    YOLO: You Only Look Once
    
  
    YOLO applies a single forward pass of a neural network to the whole image and predicts bounding boxes and class probabilities together, which makes it fast without losing much accuracy.
    
  
    Version history
    
  
    VersionWhat changedReported figures
    
    
    YOLOv1 (2015, Redmon et al.)Merges box proposal and classification into one network. 7×7 grid; each cell predicts 2 boxes but only one set of class probabilities. (paper)45 fps, 63.4% mAP on VOC2007
    
    
    YOLOv2 / YOLO9000 (2016)Adds anchor boxes (sizes chosen by k-means on the training boxes) and predicts class and objectness for every anchor, removing the one-class-per-cell limit. (paper)78.6% mAP on VOC2007 at 544×544, 40 fps
    
    
    YOLOv3 (April 2018)The reference design later versions build on. (paper)COCO AP50 44.0% (YOLOv2) → 57.9% (YOLOv3-608)
    
    
    YOLOv4 (2020, Bochkovskiy et al.)Takes over YOLO research. (paper)43.5% AP (65.7% AP50) on COCO at about 65 fps on a Tesla V100
    
    
    YOLOv5 (2020, Ultralytics)Released weeks after YOLOv4 without a peer-reviewed paper; written in PyTorch instead of Darknet. Popular in applied computer vision; the model we use.–
    
  
    
  
    Joseph Redmon stopped working on object detection in 2020, citing concerns about military use of his work. Many versions have followed from several groups: Scaled-YOLOv4, PP-YOLO, YOLOX, YOLOR, YOLOv6, YOLOv7, YOLOv8 and newer.
    
  
    

  
    The idea behind YOLO
    
  
    YOLO treats detection as a regression problem and divides the image into an S × S grid. If the centre of an object falls inside a grid cell, that cell is responsible for detecting it. Each cell outputs:
    
  
      
    
    • Box: four values x, y, w, h: (x, y) is the box centre and (w, h) its width and height.
      • 
    
    • Confidence: how likely the box contains an object and how well it fits, defined as P(object) × IoU(predicted box, true box).
      • 
    
    • Class probabilities: YOLOv3 uses independent logistic classifiers instead of a softmax, so one box can carry more than one label.
      • 
  
    
  
    
  
    YOLO in easy steps
    
  
      
    
    1. Divide the image into an S × S grid.
      2. 
    
    2. Label the training data: with C classes the output has S × S × (C + 5) values (4 box values, 1 objectness, C class scores). A 4×4 grid with 3 classes (car, light, pedestrian) gives a 4×4×8 target.
      3. 
    
    3. Train a deep CNN with a loss comparing the output with the label tensor. One forward pass predicts every grid cell.
      4. 
    
    4. An object belongs to the cell that contains its centre, so it is not counted in several cells.
      5. 
  
    
  
    This is the simplified one-box-per-cell version. YOLOv3 predicts 3 boxes per cell at each of 3 scales, so each cell outputs 3 × (C + 5) values: for COCO’s 80 classes, 3 × 85 = 255.

    YOLOv3 architecture and Darknet-53
    
  
    
  
    The YOLOv3 backbone, Darknet-53, has 53 convolutional layers built from convolutional and residual blocks. The last three layers (average pooling, fully connected, softmax) are used only to train the classifier on ImageNet and are dropped when it is used to extract features.
    
  
    
  
    Why Darknet-53: its accuracy matches much deeper classifiers but it is faster (77.2% top-1 at 78 fps, versus ResNet-101 77.1% at 53 fps and ResNet-152 77.6% at 37 fps), and it reaches the highest measured floating-point throughput (1457 BFLOP/s against 1039 and 1090), so it uses the GPU better.
    
  
    
  
    

  
    Common mix-ups to avoid. YOLOv3 uses independent logistic classifiers, not a softmax, so a box can carry more than one label. YOLOv5 was released by Ultralytics (not Redmon’s team) and is written in PyTorch, not Darknet. By contrast, the YOLOv1 speed (45 fps), the anchor boxes of YOLOv2 and its 63.4% → 78.6% VOC mAP jump are correct.
    

  
    SSD vs YOLO
    
  
      
    
    • Both detect in a single pass.
      • 
    
    • YOLOv1 ended in two fully connected layers; SSD, and YOLO from v2 onward, are fully convolutional.
      • 
    
    • SSD adds several feature layers to the end of a base network and predicts offsets to default boxes of different scales and aspect ratios, plus a score for each. YOLO from v2 onward uses anchor boxes in much the same way, and YOLOv3 predicts at 3 scales, like SSD’s multi-scale maps.
      • 
    
    • On VOC2007 (SSD paper): SSD300 74.3% mAP at 59 fps; YOLOv1 63.4% mAP at 45 fps. Faster R-CNN reaches 73.2% at 7 fps (Titan X GPU).
      •

    A pre-trained YOLOv5 on road images
    
  
    Why YOLOv5 for our problem:
    
  
      
    
    • Pre-trained models are trained on COCO, whose 80 classes already include vehicles (car, motorbike, bus, truck, bicycle), traffic light, stop sign, person, and animals such as bird, cat, dog, horse, sheep and cow. (COCO has no “deer”, which matters for road safety in some countries.)
      • 
    
    • It is written in PyTorch, widely used, and comes in five sizes (n, s, m, l, x) for different speed and memory budgets.
      • 
    
    • We use its ONNX export: ONNX is an open model format with a common set of operators and a common file format, so a model built in one framework (here PyTorch) can run in other tools (here OpenCV on a CPU, with no deep-learning framework installed).
      • 
  
    
  
    The data are 22,241 dashboard-camera images; the models used are yolov5n (nano) and yolov5s (small), and coco.names.txt lists the 80 class labels.
    
  
    
  
    The model returns one tensor per image with 25,200 candidate boxes, each with 85 values. We keep a candidate only if its final score (objectness × best class score, the probability that there is an object and that it is this class) passes a threshold (YOLOv5’s own default is 0.25), keep only driving-relevant classes, and let NMS (IoU threshold 0.45) remove duplicates.

    Class imbalance and focal loss
    
  
    Single-stage detectors such as SSD and YOLO evaluate roughly 104 to 105 candidate locations per image (8,732 for SSD300), and only a few contain an object. This class imbalance is the main reason single-stage detectors trailed two-stage detectors in accuracy. Small objects and objects close together can also be missed by YOLO-style detectors. SSD handles part of the imbalance with hard negative mining; RetinaNet changes the loss instead, with focal loss.
    
  
    Each easy background box has a tiny cross-entropy loss, but there are so many that together they dominate the total. Focal loss multiplies the loss by (1 − pt)γ, shrinking the weight of examples the model already gets right:
    
  
    FL(pt) = − αt (1 − pt)γ log(pt), with γ = 2 and α = 0.25 in the RetinaNet paper.
    
  
    
  
    
  
    The factor (1 − p_t)^gamma is the only difference from ordinary cross-entropy, and the lecture’s implementation matches torchvision’s sigmoid_focal_loss exactly (0.2552 on random logits). Setting γ = 0 turns focal loss back into weighted cross-entropy.

    Key takeaways
    
  
      
    
    • Single-stage detectors skip the proposal step and predict boxes and classes in one pass, which makes real-time detection possible.
      • 
    
    • SSD predicts from several feature maps using default boxes (8,732 for SSD300); YOLO divides the image into a grid and predicts from anchor boxes.
      • 
    
    • A pre-trained YOLOv5 runs on CPU for our driving use case without any training (183.6 ms per image in the lecture, which is still slower than real time).
      • 
    
    • Class imbalance is the main weakness of single-stage detectors; RetinaNet addresses it with focal loss.
